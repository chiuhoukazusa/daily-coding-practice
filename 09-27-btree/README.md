# B-Tree Multiway Search Tree

**日期**: 2026-09-27
**方向**: 数据结构
**核心技术**: B 树 / 多路搜索树 / 节点分裂与合并 / 借位重平衡 / 磁盘友好 / 高度平衡不变式

## 概述

B 树（B-Tree）是一种**自平衡的多路搜索树**，是数据库索引与文件系统（如 B-Tree 文件
系统、NTFS、InnoDB 索引）的核心底层结构。与二叉搜索树（BST）每个节点最多 2 个子节点不同，
B 树每个节点可容纳 **最多 `2t-1` 个键、`2t` 个子节点**（`t` 为最小度数），单次磁盘 I/O
即可读取整页数据，从而显著减少树高、降低磁盘访问次数。

本实现以最小度数 `t=3` 为例，完整实现了 B 树的五大核心操作：

- **搜索 `find`**：从根沿键区间逐层下探，单次查找 `O(log_t n)`。
- **插入 `insert`**：满节点自顶向下**预分裂**（`splitChild`），保证插入路径上无满节点，
  避免递归回溯，是 B 树最优雅的设计之一。
- **删除 `erase`**：核心难点。叶子删除、内部节点删除（用前驱/后继替换后递归下沉），
  以及下溢时的**借位（borrowFromPrev/borrowFromNext）**与**合并（merge）**。
- **中序遍历 `inorder`**：输出按键有序排列，天然支持范围查询。
- **高度不变式**：所有叶子节点必须处于同一深度。

## 实现要点

- **节点结构 `Node`**：`keys`（有序键数组）、`vals`（值数组）、`children`（子指针数组）、
  `leaf`（是否叶子）、`n`（当前键数）。键数与子节点数恒满足 `children.size() == keys.size() + 1`
  （非叶节点）。
- **分裂 `splitChild`**：当子节点已满（`2t-1` 个键）时，以中位键为界一分为二，中位键
  上浮到父节点，右半部分移入新建兄弟节点。分裂是 B 树维持每一层键数 ∈ `[t-1, 2t-1]`
  的关键。
- **删除三情形**（教科书经典分类）：
  1. 键在叶子 → 直接 `removeFromLeaf`；
  2. 键在内部节点 → 若左子节点键数 ≥ `t` 用**前驱**替换并递归删除前驱；否则若右子节点
     ≥ `t` 用**后继**替换；否则**合并**两个子节点后递归删除；
  3. 键不在当前节点 → 下探前若目标子节点键数 < `t`，先 `fill`（借位或合并）保证不越界。
- **去重语义**：插入时若键已存在则跳过（等价 `std::set` 的集合语义），保证 `inorder`
  输出严格递增。

## 量化验证（全部通过）

1. **BST 有序性**：`N=200000` 随机键插入后，中序遍历结果 `inorder_sorted=PASS`，
   且 `size() == std::set` 的规模（190241 个唯一键）`size_match=PASS`。
2. **成员查找正确性**：所有已插入键 `contains_all=PASS`；对 10000 个随机白区间
   （`2000001..4000000`）键检查 `no_false_positive=PASS`（零误报）。
3. **高度平衡**：实测树高 `h=10`，理论下界 `log_t(n)≈11.11`，满足
   `height_within_theoretical_bounds=PASS`（所有叶子同深度不变式成立）。
4. **值映射与删除**：`N2=100000` 唯一键，`value_mapping_correct=PASS`；随机删除一半后
   `size_ok=PASS` 且 `deleted_keys_absent=PASS`（被删键完全消失）。
5. **性能对比 std::set**（`N=100000` 唯一键）：
   - 插入：`std::set` 26.8ms vs `BTree` 57.7ms（set 快约 2.1x，符合 set 内存局部性预期）
   - 查找：`std::set` 37.6ms vs `BTree` 29.3ms（B 树磁盘友好设计，查找略胜）
   - 结论：内存 B 树与红黑树在查找上互有胜负，B 树的优势主要体现在**磁盘/缓存友好**
     的大数据量场景。
