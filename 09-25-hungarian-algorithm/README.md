# Hungarian Algorithm (Kuhn-Munkres) — Assignment Problem

**日期**: 2026-09-25
**方向**: 算法 / 图算法
**核心技术**: 匈牙利算法 / 带权二分图最大权完美匹配 / Kuhn-Munkres / 增广路 / 顶标（Potential）

## 概述

匈牙利算法（Hungarian Algorithm，又称 Kuhn-Munkres 算法）在 **O(n³)** 时间内求解
**指派问题（Assignment Problem）**：给定一个 `n×n` 的代价矩阵，每行恰好分配一个不同
的列，使总代价最小（等价于带权二分图的最大权完美匹配）。

经典的暴力解法需要枚举 `n!` 种排列，在 `n=13` 时即超过 60 亿种，完全不可行；贪心
（每行取当前最小剩余列）虽然快但**无法保证最优**。匈牙利算法通过「顶标 + 相等子图 +
增广路」的对偶构造，把复杂度压到多项式级，是组合优化里的经典奠基算法。

## 实现要点

- **最小代价版 `hungarianMin(cost)`**：直接求解最小总代价分配。
  - 维护行顶标 `u[i]`、列顶标 `v[j]`，满足可行性条件 `u[i] + v[j] ≤ cost[i][j]`。
  - 在相等子图（`u[i] + v[j] == cost[i][j]`）上寻找增广路，通过「松弛 + 最小可调整量
    delta」更新顶标，逐步扩大匹配。
  - 该写法（`p[]` + `way[]` + `minv[]`）是常用的 O(n³) 紧凑实现。
- **最大权版**：将代价取负（`-cost[i][j]`）转化为最小代价问题，取出最优解后再还原。
- **暴力基准 `bruteForce`**：枚举 `n!` 全排列求最小总代价，用于小 n 下验证最优性。

## 量化验证（全部通过）

1. **最优性 vs 暴力全排列**：小 n（≤8）随机代价矩阵，1600 组。
   匈牙利结果与暴力最优解 **1600/1600 完全一致**。
2. **贪心非最优性证明**：贪心逐行取最小，800 组中 **692 组（86.5%）非最优**，
   证明贪心不足、匈牙利算法必要。
3. **最大权匹配 vs 暴力**：取负转化最大权版，1200 组 **1200/1200 一致**。
4. **分配合法性**：所有解均为合法排列（每行列互异）。
5. **性能 O(n³) 验证**：n=100→0.27ms，n=200→1.50ms，n=400→5.69ms，n=800→27.56ms，
   时间随 n 增长符合立方量级。
