# Li Chao Segment Tree (Convex Hull Trick)

日期：2026-11-23
方向：数据结构 / 凸包技巧

## 技术点

- **李超线段树（Li Chao Tree）**：在 `[minX, maxX]` 坐标范围内动态插入直线 `y = m*x + b`（或限定区间的线段），并支持查询某点 `x` 上所有已插入直线的最小值，单次操作 `O(log N)`。
- **直线版 `add_line`**：动态开点，比较区间端点与中点处取值，让"中点更优"的直线驻留当前节点，另一条下推至可能更优的一侧子树。
- **线段版 `add_segment`**：仅在 `[ql, qr]` 区间内插入线段，按区间覆盖递归拆分到 Li Chao 节点。
- **点查询 `query(x)`**：从根到叶沿途取每个节点直线在 `x` 处取值的最小值。
- **凸包技巧（Convex Hull Trick, CHT）**：常用于斜率优化 DP 的 `O(n²) → O(n log n)` 加速，Test3 以"下凸壳最小值"作为经典应用验证。

## 核心思想

每条直线是树中某个节点的候选。插入时不断"交换 + 下推"：

- 若新直线在中点 `mid` 处更优（取值更小），则与当前节点直线交换；
- 被换下的直线根据左/右端点优劣，下推到可能更优的那一侧子树；
- 查询时沿树路径取最小值，天然覆盖所有可能在 `x` 处最优的直线。

这样避免了维护显式凸壳的边界/二分复杂逻辑，且对任意插入顺序稳定。

## 踩坑记录

1. **线段版暴力基准的语义**：线段只在 `[ql, qr]` 内生效，暴力基准查询时必须检查 `ql <= x <= qr` 才统计该线段，否则正确性对比失效。
2. **INF 取足够大**：`4e18` 保证未插入直线时查询返回安全的"无穷大"兜底，且不溢出 `ll`。
3. **性能对比的 sink**：暴力查询结果累加到 `sink` 并在 Li Chao 结果累加到 `sink2` 后比较，既防止死代码消除，又额外验证两者数值完全一致。
